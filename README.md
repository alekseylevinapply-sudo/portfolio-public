# Алексей Лёвин — портфолио

Статическое портфолио Java Backend Engineer: профиль, хронология опыта, четыре коммерческих кейса и резюме. HTML/CSS, без JavaScript, внешних шрифтов, аналитики, виджетов и серверного приложения.

- `index.html` — профиль, опыт, проекты, технологии и контакты в Telegram и GitHub.
- `resume.html` — резюме с оформлением для экрана и печати в PDF средствами браузера.
- `resume.md` — версия резюме для скачивания.
- `styles.css`, `favicon.svg` — оформление и иконка сайта.
- `site-leads.html` — отдельный кейс «Контур Сервис» для направления сайтов и автоматизации; `site-leads-*.png` — реальные снимки приложения.
- `jhipster-leads.html` — отдельный кейс «Контур — приём заявок» на JHipster, Java и React; `jhipster-leads-*.png` — снимки формы и кабинета оператора.

Главная и резюме сохраняют фокус на коммерческом опыте Java/backend. Кейсы доступны по прямым ссылкам `site-leads.html` и `jhipster-leads.html` для портфолио FL.ru; ссылок на них с главной нет. Исходники приложений, базы данных и рабочие настройки в этот репозиторий не входят. Для самостоятельных приложений используются отдельные репозитории с собственными README, запуском и проверками.

## Локальная проверка

Нужны Node.js и Python 3. Установка npm-зависимостей не требуется.

```sh
node scripts/build.mjs
node scripts/check.mjs
python -m http.server 8091 --bind 127.0.0.1 --directory dist
```

Открыть `http://localhost:8091/`. Сервер обслуживает только готовую статику из `dist`, а не Git-репозиторий.

## Обновление

Изменить нужные страницы и `styles.css`, собрать `dist`, проверить ссылки, мобильную версию и список изменённых файлов. Содержание `resume.html` и `resume.md` поддерживается согласованным. Сборка, проверка и публикация используют единый явный список `scripts/public-files.mjs`. Дополнительный материал добавляется в список только после проверки и согласования. PNG проверяются побайтово и по сигнатуре; содержание снимков перед переносом проверяется визуально.

Первая публичная отправка новых персональных материалов выполняется после подтверждения владельца. Коммерческий опыт и личные проекты описаны отдельно. В качестве контактов используются согласованные профили Telegram и GitHub; ссылки на код собственных разработок добавляются только после проверки их публичной доступности.

## Публикация на Codeberg Pages

Адрес сайта: https://alekseylevin.codeberg.page/.

GitHub — основной репозиторий исходников. Workflow `Publish Codeberg Pages` автоматически запускается после каждого push в `main`. Повторный запуск доступен в GitHub Actions через `Run workflow`.

После сборки и проверки только файлы из разрешённого списка в `dist` отправляются в публичный репозиторий https://codeberg.org/alekseylevin/pages, в ветку `pages`. Ветка содержит один корневой коммит `init` с текущим сайтом. Повторный запуск для неизменившегося сайта не заменяет уже подготовленный `init`. Затем workflow проверяет HTTP-ответы и точное совпадение опубликованных файлов со сборкой.

Для отправки используется отдельный SSH deploy key с правом записи только в репозиторий `alekseylevin/pages`. Закрытая часть хранится в GitHub Actions secret `CODEBERG_PAGES_DEPLOY_KEY`. Отпечаток SSH-хоста Codeberg проверяется перед подключением. Webhook Codeberg для push в `pages` уведомляет адрес сайта об обновлении.

Повтор устаревшего запуска пропускается, чтобы не вернуть старое содержимое сайта. Если ошибка произошла до отправки на Codeberg, сайт не изменяется. Если отправка прошла, но HTTP-проверка завершилась ошибкой, новая версия уже могла появиться: нужно проверить сайт и журнал GitHub Actions. После исправления можно повторить запуск для текущего `main`.

Ветка `main` также содержит один корневой коммит `init`. Перед её обновлением прежняя история сохраняется в локальном Git bundle вне репозитория. Замена публичных веток выполняется через `--force-with-lease` с ожидаемым SHA: при стороннем изменении ветки публикация останавливается. Резервные ветки и теги не публикуются.
